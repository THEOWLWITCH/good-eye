## הפעלה

אפליקציית דפדפן מקומית שלא דורשת התקנה או חיבור לאינטרנט.

- **הדרך הפשוטה:** לחיצה כפולה על `index.html` (נפתח ב־Chrome / Edge).
- **דרך שרת מקומי (מומלץ, כדי שהנתונים יישמרו תמיד תחת אותה כתובת):**
  ```bash
  python -m http.server 8765
  ```
  ואז לגלוש אל http://localhost:8765

> חשוב: הנתונים נשמרים בדפדפן (localStorage) לפי כתובת. כשפותחים את הקובץ ישירות, הנתונים נשמרים בנפרד ממה שנשמר תחת `localhost`. מומלץ לבחור דרך אחת ולהישאר איתה, ולייצא ל־JSON אחרי כל מפגש.

## אופן העבודה (לקורא)

1. מכסים את העין השמאלית ומתיישבים במרחק קבוע. רושמים את תנאי הצפייה בצד.
2. מסתכלים על הרשת ומאתרים קו שנראה עקום.
3. תופסים את הקו בדיוק במקום העקום (עכבר, מגע או עט) וגוררים עד שהקו נראה ישר.
4. אפשר לתקן כמה פעמים, באותו קו או בקווים אחרים.
5. מסיימים ב־**שמירה**, מדרגים את הביטחון בתוצאה (1–5) ומוסיפים הערות.

| פעולה | מקש |
|---|---|
| ביטול / חזרה | `Ctrl+Z` / `Ctrl+Y` |
| שמירה | `Ctrl+S` |
| הקטנה / הגדלה של רדיוס ההשפעה | `[` / `]` |
| מסך מלא | `F` |

- **רדיוס השפעה** קובע את גודל הסביבה שזזה יחד עם הנקודה. רדיוס גדול נותן תיקון רך ורחב, ורדיוס קטן נותן תיקון ממוקד.
- **הגבלת גרירה** (מופעלת כברירת מחדל) מונעת קיפול של הרשת. אם הגרירה "נעצרת", צריך להגדיל את הרדיוס.
- **ניסיון חוזר** פותח ניסיון חדש מאפס עם אותן הגדרות, ומקושר לניסיון המקורי (לבדיקת חזרתיות, סעיף 8.2).
- **השוואה לניסיון** מציגה בכחול את הרשת המתוקנת מניסיון אחר, מעל הניסיון הנוכחי.
- כל שינוי נשמר אוטומטית כטיוטה, כך שגם סגירה של הדפדפן לא מאבדת עבודה.

## המודל המתמטי

הקואורדינטות מנורמלות לריבוע הגירוי (0..1), ולכן הכיול משוחזר במדויק בכל גודל חלון.
כל גרירה היא פעולה מקומית: הנקודה שנתפסה זזה בדיוק עם המצביע, והסביבה זזה לפי גרעין חלק (Wendland C2) עד רדיוס ההשפעה.
השדה הכולל הוא הרכבה של כל הפעולות לפי הסדר, ולכן הוא שדה תזוזה דו־ממדי רציף.

**מניעת קיפולים:** הדטרמיננטה של היעקוביאן בכל פעולה היא לפחות `1 − 2.109·|δ|/r`. כל עוד היחס `|δ|/r < 0.474`, אין קיפולים, וזה נכון גם להרכבה של כל הפעולות (כלל השרשרת). המערכת מחשבת גם את היעקוביאן על רשת דגימה ומציגה בשורת המצב את טווח שינוי השטח המקומי ואת התזוזה המרבית.

## הנתונים שנשמרים בכל ניסיון (סעיף 11)

`schema: da.trial/1`: מזהה, תאריכים, גרסת תוכנה, משך הניסיון, סוג המכשיר, הגירוי (צפיפות, מצב תצוגה, עובי קו, קוטביות), מידות המסך וגודל הגירוי בפיקסלים, תנאי הצפייה (עין, מרחק, תנוחת ראש, תאורה, קיבוע), ו־**actions**.
כל פעולת גרירה ב־actions כוללת: מיקום מקורי על הקו הישר, מיקום לפני ואחרי, dx/dy, מרחק, כיוון במעלות, רדיוס, צפיפות רשת, משך הגרירה וסוג ההצבעה.
בנוסף נשמרים **eventLog** (כל הפעולות כולל ביטול, חזרה, איפוס ושינויי הגדרות), **model** (הפעולות, שדה תזוזה מדוגם ‎33×33 ומדדי איכות), הגאומטריה המקורית והמתוקנת של כל הקווים, דירוג הביטחון וההערות, ומצב ההיסטוריה המלא.

**ייצוא:** JSON כולל את כל הנתונים, ו־CSV כולל שורה לכל פעולת גרירה (מתאים ל־Excel, R ו־Python).

## מה חדש בגרסה 0.6 (כלי עזר, עבודה בלי אינטרנט, היסטוריה וסנכרון)
- **כלי עזר בלבד:** כל הניסוחים עודכנו, כך שאין באפליקציה אבחון ולא דוחות. "מבחן מהירות קריאה" נקרא עכשיו "גודל קריאה נוח", ו"מיפוי שדה ראייה" נקרא "מפת נוחות צפייה". במסך הפתיחה יש הבהרה.
- **עבודה בלי אינטרנט (באתר העצמאי):** אחרי הפתיחה הראשונה האפליקציה נפתחת ועובדת גם בלי חיבור. ספריות, גופנים ומודל העיניים נשמרים במכשיר בפעם הראשונה שמשתמשים בהם. הקובץ `sw.js` נוצר על ידי `python tools/gen_sw.py`.
- **היסטוריה (לא חובה):** בכל פרופיל יש מתג "📈 שמירת היסטוריה".
  - כשהמתג כבוי, נשמרת רק התוצאה האחרונה מכל סוג.
  - כשהוא פועל, מוצגים גרפים פשוטים של גודל הקריאה הנוח, מהירות הקריאה, תוצאות המשחק וכיולי העיוות לאורך זמן. בלי פרשנות.
- **סנכרון מוצפן בין מכשירים (באתר ב־Netlify):**
  - המכשיר הראשון יוצר "קוד משפחה" של 16 תווים, ומקלידים אותו במכשירים האחרים.
  - הנתונים מוצפנים בדפדפן (AES-GCM, מפתח שנגזר מהקוד) לפני שהם נשלחים. השרת שומר רק טקסט מוצפן, תחת גיבוב של הקוד.
  - פרופילים מתמזגים לפי העדכון האחרון. מחיקות עוברות בין המכשירים.
  - הצד בשרת: `netlify/functions/sync.mjs` עם Netlify Blobs, שמותקן אוטומטית מ־`package.json`.
  - לבדיקה מקומית: `node tools/dev-server.mjs`.
- **בדיקות:** `npm test`, או בנפרד `node tests/run-tests.js` ו־`node tests/sync-tests.mjs`.
